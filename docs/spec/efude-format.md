# .efude file format

An `.efude` file is a ZIP container. The first uncompressed entry is `mimetype` containing `application/x-efude`. `manifest.json` stores format version, canvas width/height, DPI, color space, and pixel format. New files use `RGBA8`: sparse 256×256 raster tiles with straight (non-premultiplied) alpha, exactly the in-memory representation, so saving and loading is lossless. Readers also accept `RGBA8_PREMULTIPLIED` tiles written by earlier drafts (RGB multiplied by alpha with integer rounding) and un-premultiply them. `layers.json` stores layer IDs, names, visibility, opacity, locking, clipping, sketch/reference flags, blend mode, the optional `linear_blend` flag, kind, optional `parent_id`, folder `expanded` state, mask presence, and the optional `tone` object of a screentone layer (`lines_per_inch`, `angle_degrees`, `shape`, `color`, `antialias`; see `docs/spec/comic.md`). A tone layer's pixels store density; readers that do not know tones may show them as plain grey. Missing `linear_blend` values default to `false` for older documents. A layer with `parent_id` belongs to that folder; raster children inherit parent visibility and opacity. Each tile in `tiles/<layerId>/<x>_<y>.bin` uses an LZ4 block with a four-byte little-endian uncompressed-size prefix. Missing tiles are transparent. The loader also accepts the earlier `.rgba` tile entries for compatibility. A vector layer also has `vectors/<layerId>.json`: a JSON array of strokes, each with `points` (objects with `x`, `y` in document pixels and the line `width` there), `color` (straight RGBA, 0–255) `hardness` (0–1) and, for lines drawn as curves, `anchors`: the Bézier anchor points (`x`, `y`, `width`, the handles `in_x`/`in_y` and `out_x`/`out_y` relative to the anchor, and `corner`). `points` are then the curve drawn at about one-pixel steps. Its tiles hold the drawing of those strokes, so readers that ignore vectors still show the layer. Layers are stored bottom first, and each folder's contents come directly before the folder. Optional grayscale mask tiles are stored at `masks/<layerId>/<x>_<y>.gray`; missing mask tiles mean fully white. `metadata.json`, present only when the document has any, is a JSON object of string keys to string values for document-level data: `comic` holds the manga page setup and panel layout, and `balloons` holds the text and balloon objects (JSON arrays and objects serialized as strings; see `docs/spec/comic.md`). Balloon layers also store their rendered pixels, so readers that ignore the metadata still show them. A book (`.efudebook`) is a separate JSON file listing page `.efude` files by relative path. `thumbnail.png` is a scaled preview no larger than 256×256, and `merged.png` is the full composite preview. Before building the ZIP index, readers check the ZIP or ZIP64 central directory against its declared count and size, cap directory data at 64 MiB and reject duplicate names. Readers reject archives with more than 500,000 entries or more than 2 GiB of decoded raster and mask tiles. This early format is provisional and not stable before 1.0.

Saving over an existing `.efude` file rebuilds the archive in a temporary file and atomically replaces the original. Byte-identical metadata, masks, previews, and tiles are copied from the previous ZIP entry when their uncompressed contents match. Unchanged raster tiles are compared after LZ4 decoding so their compressed LZ4 blocks can be copied without recompression. Changed entries are written anew, and entries no longer present in the document are omitted.

## Layer properties and blend modes

Each layer record in `layers.json` has the following additional properties.

| Property | JSON value | Meaning |
| --- | --- | --- |
| `alpha_lock` | Boolean, default `false` | Painting preserves the destination alpha byte. A transparent pixel receives no paint. At nonzero alpha, brush coverage blends RGB while leaving the existing alpha, including partial coverage, intact. |
| `layer_color` | `null` (default) or three integers `[r, g, b]`, each 0–255 | Tint the layer for compositing. The stored straight RGBA tiles retain the original artwork. |

For tinting, normalize the source RGB and tint components to 0–1. Compute `luma = 0.2126*r + 0.7152*g + 0.0722*b` from the source. Use `tint_c + (1 - tint_c) * luma` for each color component before layer blending, preserving alpha. Black source pixels take the tint color and white stays white. The merged preview includes the tint.

The case-sensitive `blend` values are `Normal`, `Multiply`, `Screen`, `Overlay`, `Darken`, `Lighten`, `ColorDodge`, `ColorBurn`, `HardLight`, `SoftLight`, `Difference`, `Exclusion`, `Add`, `Subtract`. These are the 14 supported modes. The reader uses `Normal` for a missing or unknown value. The proposed `LinearBurn`, `LinearDodge`, `Hue`, `Saturation`, `Color` and `Luminosity` modes are unimplemented.
